### Results

- Output bytes are identical in all three browsers. Re-encoding `already_compressed.jpg` makes it 25 % larger (18356 to 22867 bytes): the engine needs a "keep the original when the output is not smaller" rule (L2).
- `@jsquash/jpeg` 1.6.0 has no inner `new Worker`: single-threaded Emscripten modules loading their `.wasm` through `new URL(..., import.meta.url)`.
- Nested-worker issue (jSquash #19, vitejs/vite#13367): a production-build failure for a worker that creates a worker. With `worker.format` back at Vite's default `iife` the build and the tests still pass: it **does not reproduce** with this package. Packages with an inner worker are the multi-threaded builds: `@jsquash/oxipng` 2.3.0 (`pkg-parallel/.../workerHelpers.worker.js`, used by L1), `@jsquash/avif`, `@jsquash/jxl`; not covered here.
- Workaround: `worker: { format: "es" }` in `packages/spike/vite.config.ts`. For oxipng, avif and jxl the jSquash README's fix is the `single-thread-only` dist-tag (oxipng `1.0.1-single-thread-only`).

verdict: go

```
default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self'; connect-src 'self'; style-src 'self'; img-src 'self'; form-action 'none'; base-uri 'none'; frame-ancestors 'none'
```

| directive | why |
|---|---|
| `default-src 'none'` | Anything not listed below is blocked. |
| `script-src 'self' 'wasm-unsafe-eval'` | Own scripts only; `wasm-unsafe-eval` lets the page compile WebAssembly without allowing `eval`. |
| `worker-src 'self'` | Workers load from the same origin. Loosen to `blob:` only if a package spawns blob workers. |
| `connect-src 'self'` | `fetch` of `.wasm` files from the same origin; nothing can send data elsewhere. |
| `style-src 'self'`, `img-src 'self'` | Own CSS and images. |
| `form-action 'none'` | Nothing can be posted out of the page. |
| `base-uri 'none'` | Blocks injected `<base>` tags. |
| `frame-ancestors 'none'` | The app cannot be embedded. |

Loosenings so far: none. The local preview sends no CSP, so the first run under it is a human step.
